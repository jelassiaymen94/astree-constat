### 2. Conception de l’architecture

Architecture retenue :

```text
ASP.NET Core Web API
    ├── SQL Server
    └── FastAPI
            └── LLM
```

Principes :

- .NET gère les données et les règles métier ;
- FastAPI gère les prompts et le LLM ;
- SQL Server conserve les dossiers et l’historique ;
- toute sortie IA nécessite une validation humaine.

### 3. Mise en place de SQL Server

SQL Server 2022 a été démarré dans Docker et connecté à SSMS via `localhost,1433`.

La base `AstreeClaimsDb` et les tables suivantes ont été créées :

- `Clients`
- `Contrats`
- `Vehicules`
- `Sinistres`
- `GenerationLogs`

### 4. Initialisation de l’API .NET

Le SDK .NET 8.0.423 a été installé.

La solution et le projet ont été créés :

```bash
dotnet new sln -n AstreeClaims
dotnet new webapi -n AstreeClaims.Api -o backend/AstreeClaims.Api --framework net8.0 --use-controllers
dotnet sln AstreeClaims.sln add backend/AstreeClaims.Api/AstreeClaims.Api.csproj
```

Swagger a été lancé avec succès.

## Incidents rencontrés et solutions

### Commande PowerShell utilisée dans Git Bash

Le caractère de continuation PowerShell a séparé une commande .NET en plusieurs commandes Bash.

**Correction :** utiliser une seule ligne et des chemins avec `/`.

### `dotnet-ef` introuvable

L’outil global n’était pas accessible depuis Git Bash.

**Correction :** installation locale avec `.config/dotnet-tools.json`, puis utilisation de `dotnet tool run dotnet-ef`.

### Mot de passe contenant `!`

Git Bash interprétait `!` comme une expansion de l’historique.

**Correction :** entourer la chaîne de connexion avec des guillemets simples.

### Erreurs de casse C#

`build` et `useSqlServer` ont été utilisés au lieu de `builder` et `UseSqlServer`.

**Correction :** remplacement par les identifiants corrects, C# étant sensible à la casse.
